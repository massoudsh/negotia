# Negotia Web UI

رابط کاربری Next.js (App Router) روی منطق دامنه‌ی `../src`، با SQLite محلی، ورود با نشست هشت‌ساعته و تأییدهای متصل به حساب واقعی.

## راه‌اندازی حساب و داده

از ریشه پروژه وابستگی‌های هر دو بسته را نصب کنید: `npm ci` و `npm ci --prefix web`. تست کامل با `npm test` اجرا می‌شود و به هر دو بسته نیاز دارد.

برای ایجاد حساب در ترمینال تعاملی سرور:

```bash
npm run user:create -- admin@example.com "Trade Admin" admin
```

گذرواژه و تأیید آن بدون نمایش دریافت می‌شوند (۱۲ تا ۲۵۶ نویسه). نقش‌ها: `admin` و `reviewer` برای خواندن و نوشتن/تصمیم‌گیری؛ `viewer` فقط مشاهده. ثبت‌نام عمومی یا گذرواژه پیش‌فرض وجود ندارد.

پایگاه داده پیش‌فرض `data/negotia.db` است؛ برای مسیر دیگر، `NEGOTIA_DATABASE_PATH` را در محیط اجرای برنامه و فرمان ایجاد حساب یکسان تنظیم کنید. دیسک باید پایدار و قابل‌نوشتن باشد؛ SQLite برای یک استقرار تک‌گرهی است، نه فایل‌سیستم موقت یا چند replica. از پایگاه داده نسخه پشتیبان سازگار با SQLite تهیه کنید.

فضای کاری جدید خالی است. فقط برای داده نمونه، در اولین اجرا `NEGOTIA_SEED_DEMO=1` را تنظیم کنید؛ روی پایگاه موجود داده‌ای بازنویسی نمی‌کند. رکوردهای نسخه حافظه‌ای قبلی قابل بازیابی خودکار نیستند. نشست‌ها در خروج لغو می‌شوند و در production کوکی فقط روی HTTPS ارسال می‌شود. درخواست‌های نوشتن باید Origin همسان داشته باشند؛ reverse proxy باید origin عمومی را صحیح عبور دهد.

## اجرا

```bash
cd web
npm install
npm run dev
```

سپس `http://localhost:3000`.

> اجرای `next build` (بیلد production) را روی سرور واقعی/SSH انجام بده، نه داخل کانتینر توسعه.

## صفحات
- `/login` — ورود با حساب ایجادشده توسط مدیر
- `/` — لیست مکالمات (نیازمند ورود)
- `/landed-cost` — محاسبه و ذخیره بهای تمام‌شده واردات
- `/conversations/[id]` — جزئیات، خلاصه‌سازی، پیشنهاد پاسخ، بررسی پیگیری، ثبت پیش‌فاکتور
- `/approvals` — تأیید/رد درخواست‌های checkpoint انسانی

جزئیات کامل در ویکی پروژه: `entities/web-ui`.
